An embedding is a numerical representation of an object in a vector space. In artificial intelligence, embeddings are used to represent words, sentences, documents, images, audio clips, and other types of information. An embedding typically consists of a list of floating-point numbers, such as `[0.12, -0.34, 0.87, 0.21]`, where each number represents one dimension of the vector. Real embedding models usually produce vectors containing far more than four dimensions. The number of components in a vector is called its dimensionality, and different embedding models produce vectors with different dimensionalities. Embeddings allow machine learning systems to process complex information mathematically and are particularly important in semantic search, recommendation systems, clustering, and retrieval-augmented generation. Traditional keyword search primarily looks for matching words, whereas semantic search attempts to find information based on meaning. Embeddings make semantic search possible by representing queries and documents as vectors in a compatible space. Texts with related meanings may have vectors that are close together, although the quality of this relationship depends on how the embedding model was trained. An embedding model converts an input into a numerical vector by applying a learned transformation. This model is different from a generative language model, even though both may use Transformer architectures. An embedding model generally produces vectors, while a generative language model produces token probabilities and can generate text. Word embeddings were an important development in early natural language processing. Word2Vec is a well-known technique that learns word representations from surrounding words. It includes Continuous Bag of Words, which predicts a target word from its surrounding context, and Skip-gram, which predicts surrounding words from a target word. GloVe learns word representations using global word co-occurrence statistics, while FastText incorporates character-level subword information that can help represent words not explicitly encountered during training. Traditional word embeddings usually assign a single vector to each vocabulary word, which limits their ability to represent different meanings of the same word in different contexts. Contextual embeddings address this limitation by producing representations influenced by surrounding tokens. Transformer models such as BERT generate contextual representations in which the word "bank" can have different representations depending on whether the surrounding sentence discusses finance or a river. Sentence embeddings represent an entire sentence using a single vector, while document embeddings represent larger passages, articles, or documents. Some systems generate these representations by pooling token-level vectors, while others use dedicated embedding architectures trained to produce useful sentence representations. Mean pooling averages selected token representations, and other models use special tokens or learned pooling mechanisms. Embeddings can be used to compare queries and documents through mathematical similarity measures. Cosine similarity is one of the most common methods and measures the cosine of the angle between two nonzero vectors. It is calculated by dividing the dot product of the vectors by the product of their magnitudes. A cosine similarity closer to one indicates that the vectors point in similar directions, while a value near zero indicates approximate orthogonality. A negative value indicates an angle greater than 90 degrees. These values should not automatically be interpreted as probabilities that two texts have the same meaning. Euclidean distance measures the straight-line distance between vectors, while dot product similarity measures the sum of the products of corresponding vector components. For normalized vectors, cosine similarity and dot product produce the same ranking. Vector normalization scales a nonzero vector to a specified magnitude, commonly one. The appropriate similarity measure depends on the embedding model, training method, and retrieval task. A vector database stores embeddings and associated metadata to support efficient similarity search. Examples include FAISS, Qdrant, Milvus, and Chroma, while PostgreSQL can support vector search through the pgvector extension. Vector indexes accelerate the process of finding nearby vectors in large collections. Exact nearest-neighbor search compares a query with every stored vector, whereas approximate nearest-neighbor search uses specialized structures to identify likely matches more efficiently. HNSW is a widely used graph-based approximate nearest-neighbor indexing method, while IVF-based approaches partition vector collections into groups to reduce the search space. Approximate search can improve speed and scalability at the cost of potentially missing some of the closest results. Embeddings are usually stored with metadata such as document identifiers, page numbers, source paths, and timestamps. This metadata supports filtering and allows retrieved results to be traced to their original sources. In a semantic search pipeline, a user query is converted into an embedding, compared with stored vectors, and used to retrieve the most relevant candidates. These candidates can be returned directly or passed to a downstream application. In retrieval-augmented generation, documents are commonly divided into chunks, and each chunk receives its own embedding. Chunk size influences retrieval quality because chunks must preserve useful context without including excessive unrelated information. Chunk overlap can help preserve information across boundaries, although excessive overlap can increase storage costs and create redundant results. The embedding model used for queries should be compatible with the model used to encode documents. Changing the embedding model may require generating new embeddings and rebuilding the index. Some models support different encoding instructions for queries and documents because short queries and long documents have different characteristics. Embedding quality should therefore be evaluated against the intended retrieval task. Recall at k measures how many relevant items are retrieved within the first k results, while precision at k measures the proportion of those results that are relevant. Mean reciprocal rank measures how highly the first relevant result appears, and normalized discounted cumulative gain evaluates ranking quality when relevance has different grades. A reranker can further improve retrieval by examining query-document pairs and assigning more precise relevance scores. However, embeddings do not guarantee that every factual detail, logical relationship, or nuance of the original text will be preserved. Semantic search may retrieve misleading results when documents share broad subject matter but differ in actual relevance. Domain-specific terminology may require specialized embedding models or additional evaluation. Multilingual embedding models aim to represent different languages in a compatible semantic space, while image and multimodal embedding models support visual search and cross-modal retrieval. Embeddings can also retain information about their source data, so sensitive information must be handled carefully. When selecting an embedding model, developers should consider retrieval quality, language coverage, dimensionality, latency, computational cost, licensing, and deployment requirements. Understanding vector representations, similarity measures, indexing, metadata, and evaluation is essential for building effective semantic search systems and reliable RAG applications.
