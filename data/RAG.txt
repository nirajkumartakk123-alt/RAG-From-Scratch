Retrieval-Augmented Generation, commonly known as RAG, is an artificial intelligence architecture that combines information retrieval with language generation. It allows a language model to use relevant external information when answering questions instead of relying exclusively on information learned during training and the context supplied directly in a prompt. The term was introduced in a 2020 research paper by Patrick Lewis and collaborators. RAG is particularly useful when applications need to answer questions using private company documents, technical documentation, frequently updated information, or knowledge that may not be reliably available in a model's learned parameters. A typical RAG system consists of a data ingestion pipeline, an indexing mechanism, a retrieval system, and a language model that generates the final answer. The system generally operates through two major phases: indexing and query-time retrieval. During indexing, information is collected from sources such as PDFs, websites, internal documentation, databases, and other supported files. This process is called data ingestion. Different formats require different extraction methods, and PDF loaders, web loaders, and database connectors may be used to retrieve the source content. Some PDFs contain scanned images instead of selectable text, requiring optical character recognition to convert visible text into machine-readable content. Poor extraction can introduce missing words, broken sentences, and incorrect reading order, so document quality should be checked before indexing. Extracted text may require cleaning to remove irrelevant formatting, duplicated content, and unnecessary boilerplate. The next important stage is chunking, which divides large documents into smaller segments that can be retrieved independently. Smaller chunks can improve retrieval precision by isolating specific pieces of information, while larger chunks may preserve more context but introduce irrelevant content. Fixed-size chunking divides text according to a target number of characters or tokens, while recursive character splitting attempts to divide text at increasingly smaller structural boundaries. Structure-aware chunking uses headings, paragraphs, and document sections, whereas semantic chunking attempts to preserve groups of related information. Chunk size and overlap should be selected according to the source material and retrieval task. Overlap can help preserve information that crosses chunk boundaries, although excessive overlap increases storage requirements and may produce redundant search results. Each chunk can be associated with metadata such as a document ID, title, page number, source path, or timestamp. Metadata helps identify the origin of retrieved information and enables filtering based on relevant attributes. After chunking, an embedding model converts each chunk into a numerical vector representing its features in a vector space. The resulting vectors, original text, and associated metadata are stored in a searchable index. Vector databases and vector search systems such as FAISS, Qdrant, Milvus, and Chroma can support this stage. When a user submits a question, the system converts the query into an embedding using a compatible embedding model. The query vector is compared with stored document vectors, and the system retrieves the nearest or highest-scoring candidates. The number of requested candidates is often controlled by a parameter called k. For example, setting k to five requests five candidate chunks when enough eligible results exist. Retrieving more chunks does not automatically improve the answer because excessive context can introduce irrelevant information and consume the language model's context window. Top-k retrieval selects a fixed number of candidates, while similarity thresholds can exclude results whose scores fall below a chosen cutoff. Thresholds must be calibrated because similarity scores vary between models and datasets. Dense retrieval uses vector representations to identify semantically related passages, whereas sparse retrieval uses lexical features such as word frequencies. BM25 is a widely used lexical ranking algorithm that can perform well when queries contain exact terms, identifiers, product names, or technical expressions. Dense retrieval can find relevant information even when the query and document use different wording. Hybrid retrieval combines dense and sparse search signals, potentially improving results when both semantic meaning and exact terminology matter. Reciprocal rank fusion is one method of combining rankings from multiple retrieval systems. A reranker can then evaluate candidate query-document pairs to improve their ordering. Cross-encoder rerankers typically process the query and each candidate passage together, providing a more detailed relevance assessment at the cost of additional computation and latency. Once retrieval is complete, the system constructs a prompt containing the user's question and the selected evidence. This process is called context assembly or prompt construction. The prompt may instruct the model to answer using the provided evidence, avoid unsupported claims, and acknowledge when the available information is insufficient. The language model generates the final response using the assembled context. Some RAG applications also provide citations that identify the source documents or passages supporting individual claims. Reliable citations help users verify the answer, but they require accurate associations between claims and source evidence. Retrieved information is not automatically correct or trustworthy because documents may contain outdated information, factual errors, or malicious instructions. A secure RAG system should treat retrieved content as data rather than automatically obeying instructions embedded within it. Access controls must also ensure that users can retrieve only documents they are authorized to access. This is especially important in enterprise environments containing confidential or sensitive information. RAG is useful for customer-service assistants, internal knowledge assistants, technical support applications, legal research, document analysis, and enterprise search. Unlike retraining a language model whenever information changes, a RAG system can often incorporate new documents by updating its index. However, changing the embedding model may require regenerating existing vectors, and maintaining an accurate knowledge base requires tracking document updates, deletions, and indexing failures. Incremental indexing can process changed documents without rebuilding the entire collection, while deduplication can prevent repeated content from dominating search results. Evaluation is essential for determining whether a RAG system retrieves relevant evidence and generates accurate answers. Retrieval evaluation examines whether the necessary information is found and ranked appropriately, while generation evaluation examines whether the final answer is correct, relevant, and supported by the retrieved context. RAGAS provides metrics and tools for evaluating RAG applications. Context precision measures the relevance of retrieved passages, context recall measures whether the necessary information has been retrieved, faithfulness evaluates whether generated claims are supported by the supplied context, and answer relevance measures how well the response addresses the question. These metrics should be combined with representative test questions and human review where appropriate. Common RAG problems include poor document extraction, inappropriate chunk sizes, weak embeddings, missing evidence, irrelevant retrieval, and unsupported generation. Possible improvements include hybrid search, reranking, query rewriting, metadata filtering, improved document parsing, and better source selection. Advanced RAG systems may perform multiple retrieval steps, decompose complex questions into smaller queries, or use agents to decide which sources to search. Ultimately, reliable RAG requires coordinated attention to data quality, retrieval, prompt construction, access control, evaluation, and continuous monitoring.
